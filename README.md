# Қalta

Финансовый трекер — учёт расходов/доходов, долги, категории, тема и акцентный цвет, локализация (Рус/Қаз/Eng). PWA — можно добавить на домашний экран телефона и пользоваться без сети.

Открыть: см. ссылку GitHub Pages в настройках репозитория (Settings → Pages).

## Как хранятся данные

- **Всегда локально** (localStorage): приложение полностью работает без интернета и без Firebase. Service worker (`sw.js`) позволяет запускать его офлайн.
- **Опционально — облако** (Google-аккаунт + Firestore): синхронизация между устройствами, одновременная работа с нескольких устройств на одном аккаунте, офлайн-очередь (правки, сделанные без сети, доезжают позже).

## Включить синхронизацию

1. [console.firebase.google.com](https://console.firebase.google.com) → Add project
2. Authentication → Sign-in method → включить **Google**; Settings → Authorized domains → добавить домен GitHub Pages (`<user>.github.io`)
3. Firestore Database → Create database
4. Project settings → General → Your apps → Add app → Web (`</>`)
5. Скопировать объект `firebaseConfig` в `firebase-config.js` (пример внутри файла)
6. Firestore Database → Rules → вставить содержимое `firestore.rules` → Publish
7. Желательно: в Google Cloud Console ограничить API-ключ по HTTP referrer (ключ публичный, защита данных — в `firestore.rules`)

## Как устроена синхронизация (несколько устройств)

Код — `sync-engine.js` (без зависимостей от DOM, покрыт тестами).

```
users/{uid}/ops/{id}        одна операция = один документ
users/{uid}/debts/{id}      один долг = один документ (открытые и закрытые)
users/{uid}/meta/settings   язык, акцент, стиль, категории (тема светлая/тёмная — локально на устройстве)
```

- Каждый документ несёт `_u` (монотонная метка изменения) и `_d` (id устройства). Конфликты решаются **по одной записи**, а не по всей базе.
- Удаление — «надгробие» (`_del`), поэтому устройство, бывшее офлайн, не воскрешает удалённое.
- Побеждает запись с более поздней меткой. Сервер Firestore метки не сравнивает (побеждает последняя пришедшая), поэтому устройство, увидев, что в облаке лежит более старая версия, чем его собственная, перезаписывает её — так все устройства сходятся к одному состоянию.
- Долги пишутся **полевыми патчами** (`increment` для `paid`, `arrayUnion` для журнала погашений): погашения с двух устройств одновременно складываются, а не затирают друг друга.
- Несохранённая локальная правка не перезаписывается входящей; она уходит в облако с более новой меткой.
- Первый вход на устройстве: дожидается ответа сервера. Аккаунт пуст и на устройстве только демо-данные → начинаем с чистого листа (демо не загружается). В аккаунте уже есть данные → облако побеждает, демо отбрасывается; реальные данные, созданные на устройстве до входа, добавляются.
- Вход под **другим** аккаунтом на том же устройстве: локальные данные предыдущего аккаунта сбрасываются (копия кладётся в `localStorage["qalta-backup-before-switch"]`), чтобы два набора данных не смешались.
- Всё, что приходит из облака, проходит валидацию схемы.

## Разработка

```bash
node --test tests/sync-engine.test.js   # движок синхронизации: 2–3 устройства, офлайн, конфликты, fuzz на сходимость
```

`index.html` — самораспаковывающийся бандл (разметка + `Component` внутри JSON-блока `__bundler/template`).

Правила Firestore (`firestore.rules`) не прогонялись в эмуляторе — проверьте их в Rules Playground перед публикацией.
