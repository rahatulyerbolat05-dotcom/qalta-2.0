# Qalta 4 (alpha)

Учёт личных денег вокруг одной цифры: сколько можно потратить сегодня, чтобы деньги на счетах дотянули до выбранной даты. PWA, работает без сети, данные на устройстве (IndexedDB).

## Запуск

```bash
npm install
npm run dev        # разработка
npm test           # 71 тест: логика прототипа, разбор фразы, категории, калькулятор, цифра дня, переводы, слияние при синхронизации, суперэллипс
npm run typecheck  # TypeScript strict
npm run build      # сборка + заставки iOS, CSP, service worker, проверка бюджета первого экрана
```

## Главное правило — быстрый запуск

- `index.html` сам рисует первый кадр: слой цвета Dawn (#F4EFE6), под ним скелет экрана «Сегодня» с последней цифрой дня из `localStorage`.
- Фаза 1: слой Dawn растворяется, как только приложение получило данные (или через 1,2 с, если бандл грузится долго). Фаза 2: элементы экрана поднимаются на 8 px с шагом 40 мс.
- Если бандл опоздал, скелет поднимается первым, а приложение встаёт на его место без повторной анимации (`html.late.static`).
- Service worker отдаёт оболочку из кэша. JavaScript первого экрана ограничен 80 КБ gzip, сборка падает при превышении (сейчас около 44 КБ).
- Заставки iOS (`apple-touch-startup-image`) — сплошной Dawn под размеры iPhone, генерируются при сборке.

## Вход через Google и синхронизация

- Firebase (проект `qalta-by-yerbo`) загружается только после первого экрана и только если на устройстве уже входили, либо по кнопке «Войти через Google».
- В облаке: `users/{uid}/accounts/{id}`, `users/{uid}/txs/{id}`, `users/{uid}/meta/q4`. Слияние по записям: побеждает более позднее `updatedAt`, удаление — запись с `deleted: true`.
- Правила: `firestore.rules` — один и тот же файл в корне репозитория и в `v4/` (CI проверяет, что они совпадают): правила прототипа плюс коллекции Qalta 4. Пока правила не опубликованы, облако отклонит запись, а приложение покажет это в профиле.
- Вход на iPhone с экрана «Домой» надёжен на Firebase Hosting (`*.web.app`): помощник входа живёт на том же домене, и Safari не блокирует его хранилище.
- Вход под другим Google-аккаунтом на том же устройстве: сначала копия данных в `localStorage["qalta4:backup-before-switch"]`, потом чистый старт; если копию сохранить не удалось, вход отменяется.

## Выкладка на Firebase Hosting

Qalta 4 выкладывается на отдельный сайт `qalta-v4.web.app` того же проекта, чтобы прототип на `qalta-by-yerbo.web.app` продолжал работать.

```bash
cd v4
npx firebase-tools login                              # один раз, в браузере
npx firebase-tools hosting:sites:create qalta-v4      # один раз: второй сайт проекта
npm ci && npm run build
npx firebase-tools deploy --only hosting,firestore:rules
```

После первой выкладки проверьте в консоли Firebase: Authentication → Settings → Authorized domains — там должен быть `qalta-v4.web.app` (если нет, добавьте). Без этого вход через Google на новом адресе не пройдёт.

## Конверты и ритуал гонорара

- Конверт — отложенные деньги с назначением: резерв, цель (с суммой) или обязательное. Правило: процент каждого дохода, фиксированная сумма или вручную (`src/domain/envelopes.ts`).
- Новый доход сразу открывает лист распределения: сначала фиксированные суммы, потом проценты, округление до сотен, цель не берёт больше, чем ей осталось. Суммы можно поправить; подтверждение — свайп вправо (или нажатие на ползунок для VoiceOver и клавиатуры), затем экран «Готово».
- Деньги в конвертах не входят в цифру дня. Расход «из конверта» уменьшает конверт и не трогает сегодняшнюю цифру.
- Удаление конверта возвращает его деньги в свободные.

## Суперэллипсы, движение, свайпы

- Углы: сглаживание 60 % по методу Figma (`src/ui/squircle.ts`), одинаково во всех браузерах через `clip-path`.
- Пружины: настоящая пружинная кривая, переведённая в CSS `linear()` (`src/ui/motion.ts`); переходы вкладок со стороны, плавающая плашка вкладок, счётчик цифры дня, лист с инерцией и резиной.
- Свайпы: строка влево — удалить, вправо — повторить; лист вниз — закрыть; сумма вбок — стереть цифру; экран вбок — соседняя вкладка.

## Структура

```
src/domain/   чистая логика: logic.js, parse.js, cat.js (из qalta-2.0), calc.ts, daily.ts
src/data/     store.ts — данные в памяти + запись в IndexedDB (Dexie), запасной режим без хранилища
src/ui/       токены и стили, суперэллипсы (corner-shape или clip-path для Safari), компоненты
src/app/      экраны: Сегодня, Деньги, Люди; листы: запись с калькулятором, начальная настройка
tools/        postbuild.mjs
tests/        node --test
```

## Отличия от плана в документе

- Preact вместо React: React + ReactDOM занимают около 60 КБ gzip и съели бы бюджет первого экрана.
- Данные держатся в памяти целиком, IndexedDB — только для записи: так экран не ждёт базу.
- Service worker написан вручную (около 30 строк), без vite-plugin-pwa.
