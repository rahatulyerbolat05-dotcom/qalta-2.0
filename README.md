# Қalta

Финансовый трекер: расходы и доходы, остатки на наличных и карте, месячный бюджет, долги, категории. Русский, казахский, английский; валюта — тенге. PWA: ставится на экран «Домой» и работает без сети. Вход через Google включает синхронизацию между устройствами.

Дизайн следует Apple Human Interface Guidelines (светлая и тёмная темы, системный шрифт, Dynamic Type, стекло только на слое управления). Почему приложение устроено именно так и на какие исследования это опирается — [docs/UX-SPEC.md](docs/UX-SPEC.md).

## Запуск и разработка

```bash
npm run build                          # src/ → index.html
python -m http.server 8820             # открыть http://localhost:8820/
npm test                               # тесты без браузера
node tools/cdp.js tools/e2e/flows.js   # сценарии в настоящем браузере (нужен Microsoft Edge)
```

Структура и сборка описаны в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Как хранятся данные

- **Всегда локально** (`localStorage`): приложение полностью работает без интернета и без Firebase; `sw.js` позволяет запускать его офлайн. Если браузер отказывает в записи, приложение показывает предупреждение.
- **Необязательно — облако** (Google-аккаунт + Firestore): синхронизация, одновременная работа с нескольких устройств на одном аккаунте, очередь правок без сети.
- В приложении нет демо-данных. Остатки и бюджет задаёт сам человек; пока они не заданы, на экране нет выдуманных цифр.

## Хостинг на Firebase

Конфиг — `firebase.json`, проект — `.firebaserc` (`qalta-by-yerbo`). Заголовки безопасности и кэш заданы в `firebase.json`.

```bash
npx firebase-tools login                                    # один раз, в браузере
npx firebase-tools deploy --only hosting,firestore:rules    # сайт + правила Firestore
```

Адреса `*.web.app` и `*.firebaseapp.com` Firebase добавляет в Authorized domains сам. После изменения набора синхронизируемых полей правила Firestore нужно опубликовать заново (команда выше).

## Включить синхронизацию в новом проекте Firebase

1. [console.firebase.google.com](https://console.firebase.google.com) → Add project
2. Authentication → Sign-in method → включить **Google**
3. Firestore Database → Create database
4. Project settings → General → Your apps → Add app → Web (`</>`)
5. Скопировать объект `firebaseConfig` в `firebase-config.js`
6. Опубликовать `firestore.rules` (Rules → Publish или `firebase deploy --only firestore:rules`)
7. Желательно: в Google Cloud Console ограничить API-ключ по HTTP referrer (ключ публичный, защита данных — в правилах)

## Как устроена синхронизация

Код — `sync-engine.js` (без DOM, покрыт тестами, включая случайные сценарии на трёх устройствах).

```
users/{uid}/ops/{id}        одна операция = один документ
users/{uid}/debts/{id}      один долг = один документ (открытые и закрытые)
users/{uid}/meta/settings   язык, акцент, категории (цвета, иконки), бюджет, начальные остатки
```

- Каждый документ несёт `_u` (монотонная метка изменения) и `_d` (id устройства). Конфликты решаются **по одной записи**, а не по всей базе.
- Удаление — «надгробие» (`_del`), поэтому устройство, бывшее офлайн, не воскрешает удалённое. Отмена удаления — повторная запись с более новой меткой.
- Побеждает запись с более поздней меткой. Сервер Firestore метки не сравнивает (побеждает последняя пришедшая), поэтому устройство, увидев в облаке более старую версию, чем своя, перезаписывает её.
- Долги пишутся **полевыми патчами** (`increment` для `paid`, `arrayUnion` для журнала возвратов): возвраты с двух устройств складываются, а не затирают друг друга.
- Несохранённая локальная правка не перезаписывается входящей.
- Первый вход на устройстве ждёт ответа сервера. Если на устройстве нет ничего своего, оно берёт данные аккаунта. Реальные данные, созданные до входа, добавляются к облачным.
- Вход под **другим** аккаунтом на том же устройстве сбрасывает локальные данные предыдущего аккаунта (копия лежит в `localStorage["qalta-backup-before-switch"]`).
- Всё, что приходит из облака, проходит проверку схемы.

Правила Firestore (`firestore.rules`) не прогонялись в эмуляторе; проверьте их в Rules Playground перед публикацией.
